# 修改文档

## 📋 修改概述

本次修改为系统添加了完整的前端权限控制，根据用户角色（教师、学生、管理员）动态显示/隐藏相应的功能按钮和菜单项。

## 🔧 修改内容（权限与导航、页面）

### 1. 创建权限工具函数

**文件**: `src/utils/permissions.js`

创建了统一的权限检查工具函数，包括：

- `getCurrentUser()` - 获取当前登录用户
- `isAdmin()` - 检查是否为管理员
- `isTeacher()` - 检查是否为教师
- `isStudent()` - 检查是否为学生
- `hasManagePermission(course)` - 检查是否有课程管理权限
- `canCreateCourse()` - 检查是否可以创建课程
- `canPublishHomework()` - 检查是否可以发布作业
- `canCreateQuiz()` - 检查是否可以创建测验
- `canGradeHomework()` - 检查是否可以批改作业
- `canViewAnalytics()` - 检查是否可以查看数据分析
- `canManageResources()` - 检查是否可以管理资源
- `canCreateVote()` - 检查是否可以创建投票
- `canPinDiscussion()` - 检查是否可以置顶讨论
- `canEditPost(post)` - 检查是否可以编辑帖子
- `canDeletePost(post)` - 检查是否可以删除帖子
- `canEditCourse(course)` - 检查是否可以编辑课程
- `canDeleteCourse(course)` - 检查是否可以删除课程
- `canJoinCourse()` - 检查是否可以加入课程
- `canSubmitHomework()` - 检查是否可以提交作业
- `canTakeQuiz()` - 检查是否可以参加测验
- `canVote()` - 检查是否可以参与投票

## ⚠️ 注意事项

1. **前端权限控制仅用于UI展示**
   - 前端权限控制可以提升用户体验，但不能替代后端验证
   - 所有API调用仍需后端进行权限验证

2. **用户信息存储**
   - 当前使用localStorage存储用户信息
   - 用户信息在登录时从后端获取并存储
   - 登出时清除用户信息

3. **权限检查时机**
   - 组件加载时检查权限
   - 用户角色变化时自动更新UI
   - 建议在路由层面也添加权限检查

4. **安全性**
   - 前端权限可被绕过（修改localStorage）
   - 必须在后端API中进行权限验证
   - 使用JWT token验证用户身份

## 🚀 后续优化建议

1. **路由守卫**
   - 添加路由级别的权限检查
   - 无权限时自动跳转到首页或显示提示

2. **权限缓存**
   - 可以考虑缓存权限检查结果
   - 减少重复的localStorage读取

3. **权限提示**
   - 当用户尝试访问无权限功能时，显示友好的提示信息
   - 可以引导用户联系管理员

4. **细粒度权限**
   - 可以扩展权限系统支持更细粒度的控制
   - 例如：助教角色、课程协作者等
